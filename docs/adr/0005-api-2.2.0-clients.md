# ADR 0005: API 2.2.0 clients replace 2.0.0; error-code enums stay open

- **Status:** Accepted
- **Date:** 2026-10-08
- **Decision by:** Eric Fitzgerald (human-made architectural decision)

## Context

tmi `main` moved the API schema from 2.0.0 to 2.2.0: a new `OAuthError` schema for
OAuth, SAML and discovery error responses, an `Error.error` enum of 23 codes, a
33-code `OAuthError.error` enum, and 429/422 responses on more operations.
`versions.json` lists only `main`, so regenerating produces `v2.2.0` / `v2_2_0` client
directories and would prune `v2.0.0` / `v2_0_0`.

Issue #68 (urllib3 floor `>=2.8.0`) was fixed in the generator and in the 2.0.0
clients but not yet released.

Generated clients enforce spec enums: the Python model raises on any value outside
the enum, and the TypeScript enum-guard patch makes `instanceOfX()` reject one. An
error response carrying a code the server adds later would then fail to parse
(Python) or not be recognized as an error (TypeScript).

## Decision

1. Regenerate for API 2.2.0 and **drop the 2.0.0 clients** (directories pruned). There
   are no further 2.0.x client fix releases (ADR 0003's nearest same-minor directory no
   longer exists for 2.0).
2. **Ship the urllib3 fix with the 2.2.0 Python release**, not as a separate 2.0.1. The
   2.2.0 client must declare `urllib3>=2.8.0`; `test_diagram_fixes.py` asserts it.
3. **Exempt the error-code enums from strict checking**: `Error.error` and
   `OAuthError.error` accept codes outside the spec enum. Python drops the generated
   `error_validate_enum` validators (`patch_error_code_enums`); TypeScript adds
   `ModelError.error` and `OAuthError.error` to `ENUM_GUARD_EXEMPT`. Go never enforced
   the enum. Each language's regression test decodes an unknown code.

## Consequences

- Go import paths change to `github.com/ericfitz/tmi-clients/go-client-generated/v2_2_0/v2`.
- Clients built for 2.2.0 keep handling errors from a newer server; callers that branch
  on the code must treat an unknown one as generic.
- Users pinned to 2.0.x clients get the urllib3 fix only by upgrading to 2.2.0.
